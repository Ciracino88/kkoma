# 설계: 예배 프레젠테이션 컨트롤러

> kkoma를 "파일 저장소"에서 **교회 예배 진행용 웹 프레젠테이션 컨트롤러**로 확장하기 위한 설계 문서.
> 배경/제약: [PROJECT_STATUS.md §0](../PROJECT_STATUS.md) · 상태: **구현 중(Phase 0~2 + 출력 개선)** · 최초 2026-07-23 · 갱신 2026-07-26 (구현 현황은 §14 이하)

---

## 1. 목표 & 범위

**한 문장**: 매주 받는 PPT를 브라우저에서 열어 슬라이드를 띄우고 넘기며, 필요할 때 플로팅 버튼으로 영상 플레이어를 오버레이로 열고/닫는다. 투 스크린(조작 화면 + 송출 화면) 환경.

### In scope
- 로컬 `.pptx`를 **브라우저에서 직접** 열어 슬라이드 표시·이전/다음 이동
- PPT 안 **임베드 영상 자동 추출 → 플로팅 플레이어**로 재생 (무손실)
- **투 스크린**: 같은 PC의 2번째 모니터/프로젝터에 송출, 1번 화면에서 조작
- 주차별 **영상 재생목록**(그 주 PPT의 영상 + 선택적으로 R2에 저장된 재사용 영상)

### Out of scope (현재)
- PPT **편집** (표시·제어만)
- PPT **저장/업로드**(휘발성 — 그 주 1회 쓰고 폐기)
- PowerPoint **애니메이션/전환효과** 재현 (실제 덱엔 없음 → 후순위)
- 인증 (기존과 동일하게 공개 앱)

---

## 2. 핵심 설계 원칙

1. **클라이언트 완결 · 휘발성.** PPT는 서버로 안 올라가고 브라우저 메모리에서만 처리. 저장·백엔드·서버 변환 불필요(File API + 클라이언트 파싱).
2. **영상과 슬라이드를 분리.** 슬라이드는 "정적 화면"으로 렌더, 영상은 뽑아내서 우리 플레이어로 재생. (PPT 임베드 영상 재생을 렌더러에 의존하지 않음.)
3. **조작/송출 분리.** 1번 화면(조작 UI) ↔ 2번 화면(송출 뷰)을 별도 창으로 띄우고 상태만 동기화.
4. **저장은 "재사용 영상"에만.** 매주 바뀌는 PPT는 저장 안 함. 반복 쓰는 찬양/율동 영상만 기존 R2 라이브러리에 남겨 재생목록에 합류(선택).

## 3. 아키텍처 개요

```mermaid
flowchart LR
  subgraph Browser[브라우저 (같은 PC)]
    subgraph Op[조작 창 — 1번 화면]
      P[.pptx 선택<br/>File API] --> Parse[클라이언트 파싱<br/>JSZip]
      Parse --> Slides[슬라이드 렌더<br/>pptx 렌더러]
      Parse --> Vids[영상 추출<br/>Blob URL]
      Ctrl[조작 UI<br/>슬라이드 네비 · 플로팅 버튼]
    end
    subgraph Pres[송출 창 — 2번 화면 전체화면]
      View[현재 슬라이드 + 영상 오버레이]
    end
    Ctrl <-->|BroadcastChannel<br/>상태 동기화| View
  end
  R2[(R2 미디어 라이브러리<br/>재사용 영상 · 선택)] -.->|재생목록 보강| Ctrl

- **PPT 경로**: 완전 클라이언트, 서버 없음.
- **R2 경로**: 기존 Vercel 함수 + R2 그대로 유지하되, 이제 "반복 재사용 영상 보관소" 역할로 재정의(선택적 재생목록 소스).

## 4. PPT 처리 파이프라인 (클라이언트)

`.pptx`는 zip이므로 브라우저에서 다음을 수행:

1. **압축 해제** — `JSZip`으로 로드.
2. **슬라이드 순서 파악** — `ppt/presentation.xml` + `ppt/_rels/presentation.xml.rels`로 슬라이드 순서(rId → slideN) 결정.
3. **슬라이드 렌더** — 렌더러로 각 슬라이드를 화면(HTML/SVG 또는 Canvas)으로 변환. (§5)
4. **영상 추출 & 매핑** — 각 `ppt/slides/_rels/slideN.xml.rels`에서 `video`/`media` 관계를 찾아 `ppt/media/*.mp4`를 Blob으로 추출하고 **슬라이드 인덱스에 매핑**. (실증: 샘플 덱 slide2→media1, slide3→media2, slide8→media3.)
5. **결과 모델 생성** — `{ slides: RenderedSlide[], videosBySlide: Map<slideIndex, VideoRef[]> }`.

> 메모리 최적화: 영상은 **필요할 때 지연 추출**(해당 슬라이드 도달 또는 플레이어 오픈 시)하고, 다 쓰면 `URL.revokeObjectURL`로 해제. 492MB급 대형 영상 때문에 필수.

## 5. 슬라이드 렌더링 방식 — 핵심 결정 (프로토타입으로 확정)

브라우저에서 `.pptx`를 화면으로 그리는 **클라이언트 렌더러**를 쓴다(서버 변환 없음). 후보:

| 라이브러리 | 방식 | 특징 | 비고 |
| --- | --- | --- | --- |
| **aiden0z/pptx-renderer** | HTML/SVG | 고피델리티 지향, 시각 회귀 테스트(187+ 도형·SmartArt), 텍스트 선명 | 피델리티 1순위 후보 |
| **PptxViewJS** (gptsci) | Canvas | 클라이언트 전용, 프레임워크 무관, 차트 지원 | 통합 간단 |
| **ChristopherVR/pptx-viewer** | HTML/CSS | 파싱+렌더+PNG/SVG/PDF 내보내기, React19 지원 | 기능 폭 넓음 |
| pptxjs(레거시) | HTML | 오래됨, jQuery 의존 | 비권장 |

- **접근**: Phase 0에서 상위 2개(**pptx-renderer**, **PptxViewJS**)를 **실제 「3과 예배 PPT」로 렌더 비교** → 텍스트 슬라이드(1·4·5·6·7·15)와 이미지 슬라이드(9~14) 재현 품질로 선택.
- **영상 슬라이드(2·3·8)**: 렌더러가 영상을 못 틀어도 무방(포스터/첫 프레임만 보이면 됨). 재생은 우리 플레이어가 담당.

### Plan B (피델리티 부족 시)
클라이언트 렌더 품질이 예배에 못 미치면: **주간 PPT를 PowerPoint에서 PDF로 저장 → `PDF.js`로 표시**(재현 매우 안정적) + **영상은 원본 pptx에서 별도 추출**하는 하이브리드. 사용자 손이 한 번 더 가지만(“PDF로 저장”) 저장은 여전히 불필요하고 화면 품질이 확실.

## 6. 영상 & 플로팅 플레이어

- **소스**:
  1. 그 주 PPT에서 추출한 영상(주 소스, 슬라이드에 매핑됨)
  2. (선택) R2 라이브러리의 재사용 영상 — 반복 쓰는 찬양/율동
- **재생목록**: 위 소스를 합쳐 주차별 목록 구성. 항목 = `{ label, src(BlobURL|R2 URL), fromSlide? }`.
- **플로팅 토글**: 조작 화면의 FAB(플로팅 버튼)로 송출 화면 위 **영상 오버레이 열기/닫기**. 슬라이드 진행 중 언제든 열고 닫힘(별도 창 여닫기 불필요).
- **동작**: 현재 슬라이드에 매핑된 영상이 있으면 원클릭 재생, 없으면 목록에서 선택. 재생/일시정지/다음.
- **연출**: 오버레이는 송출 화면 전체(또는 큰 박스). 재생 종료 시 자동으로 슬라이드로 복귀(옵션).

## 7. 투 스크린 프레젠테이션

- **구성**: 같은 PC + 2번째 모니터/프로젝터. 네트워크 동기화 불필요.
- **방식**: 조작 창에서 `window.open('/present')` → 2번 모니터로 드래그 → 전체화면(F11 또는 Fullscreen API). 송출 창은 현재 슬라이드/영상만 렌더.
- **상태 동기화**: **BroadcastChannel**(동일 브라우저·동일 오리진)로 조작 창 → 송출 창 메시지 전달. 대안 postMessage. (Presentation API는 지원 한계로 미채택.)
- **메시지 예**: `GOTO_SLIDE(index)`, `OPEN_PLAYER`, `PLAY_VIDEO(id)`, `PAUSE`, `CLOSE_PLAYER`.
- **주의**: PPT는 조작 창 메모리에 있으므로, 렌더된 슬라이드 이미지/Blob URL을 송출 창과 공유하는 방식 결정 필요(같은 오리진이면 Blob URL 공유 가능 / 또는 렌더 결과를 송출 창에서 재생성).

## 8. 화면 & UX 흐름

**조작 창(1번 화면)**
- 상단: PPT 열기(파일 선택), 현재 파일명, 송출 창 열기 버튼
- 좌: 슬라이드 썸네일 목록(현재 위치 표시, 영상 슬라이드 배지)
- 중앙: 현재 슬라이드 미리보기 + 이전/다음(키보드 ←/→, PageUp/Down)
- 우하단: **플로팅 영상 버튼**(재생목록 열기/토글)

**송출 창(2번 화면)**
- 현재 슬라이드 전체화면
- 영상 오버레이(플레이어) — 조작 창 신호로 표시/숨김

## 9. 상태 모델(개략)

```
Deck        { fileName, slides: RenderedSlide[], videosBySlide: Map<int, VideoRef[]> }

조작 창이 단일 진실원(source of truth), 송출 창은 수신·렌더만.

## 13. 단계별 계획

- **Phase 0 — 타당성 프로토타입** (게이트): 로컬 pptx 열기 → 슬라이드 렌더(2개 라이브러리 비교) + 영상 추출·재생. 실제 「3과 예배 PPT」로 **피델리티·메모리 실측**. → D1/D2 결정.
- **Phase 1 — 조작 뷰(단일 화면)**: 파일 열기, 썸네일, 슬라이드 네비, 키보드.
- **Phase 2 — 투 스크린**: 송출 창 + BroadcastChannel 동기화, 전체화면.
- **Phase 3 — 플로팅 플레이어 + 재생목록**: PPT 영상 매핑 재생, 플로팅 토글.(+선택: R2 라이브러리)
- **Phase 4 — 마감**: 자동 복귀, 키보드/단축키, 메모리 최적화, 예배 리허설.

> 다음 착수: **Phase 0 프로토타입**. 여기서 렌더러/피델리티가 확정돼야 나머지 설계가 확정된다.

## 14. 구현 현황 (2026-07-25)

Phase 0~2 초기 구현 완료(브랜치 `feat/presentation-controller`).

- **렌더러 확정**: `@aiden0z/pptx-renderer`(클라이언트, HTML/SVG, lazyMedia). 임베드 영상은 자리표시자로 렌더 → 우리 플레이어가 재생.
- **역할(사용자 확정, 초안과 반대)**: **1스크린 = 대중용 출력**(렌더만), **2스크린 = 조작**(PPT·영상·**음악** 제어).
- **라우트**(해시): `#present` = 조작 창(2스크린), `#present-output` = 출력 창(1스크린).
- **동기화**: `BroadcastChannel('kkoma-present')`. File/Blob 은 구조화 복제로 창 간 전달(참조 공유). Blob URL 은 받는 창에서 생성.
- **음악**: 조작 창에서 로컬 오디오 파일 추가 → 재생/일시정지/정지 지시 → 출력 창이 오디오 재생. (R2 라이브러리 연동은 후속.)
- **코드**: `src/present/` — `channel.ts`, `useDeck.ts`, `pptx.ts`(영상 추출), `ControlScreen.tsx`, `OutputScreen.tsx`. `src/main.tsx` 해시 라우팅.

## 14.1 갱신 (2026-07-26) — 출력 개선 (`b2685e2`)

- **출력 전체화면 채움 수정**: 렌더러 `fitMode:'contain'` 은 실제로 **컨테이너 *너비*에 맞춤**(높이 아님)이라 기존 `!important` 높이 강제 CSS와 충돌해 화면을 못 채웠음. **최종 방식**(결정적): 슬라이드를 **원본 크기(`useDeck` 노출 `slideWidth`/`slideHeight`)로 렌더**한 뒤, `scale = min(창너비/w, 창높이/h)` 를 **직접 `transform: translate(-50%,-50%) scale()`** 로 적용해 중앙 레터박스로 꽉 채움. 렌더러 fit 내부 동작에 의존하지 않아 창 비율과 무관하게 정확하고, `window.resize` 로 재계산.
- **영상 소스 확장**: PPT 내장 영상뿐 아니라 **로컬 파일·R2 라이브러리(mp4)** 재생. 채널 메시지 `VIDEO_PLAY_URL`(R2 URL, 창 간 유효)·`VIDEO_PLAY_FILE`(로컬 File 구조화 복제 → 출력 창에서 Blob URL 생성·해제) 추가.
- **PPT/영상 모드 토글**: 출력 화면을 `ppt`/`video` 모드로 분리(채널 `MODE`). 컨트롤러에 세그먼트 토글 추가, **영상 재생 시 자동으로 영상 모드 전환**, "정지·PPT로" 로 복귀(복귀 시 영상 정지). HELLO 핸드셰이크에 현재 모드 재전송 포함. (기존 "영상 슬라이드 홀딩 화면"은 모드 기반 영상 화면으로 대체.)
- **다음 슬라이드 미리보기**: 컨트롤러에서 현재+다음 슬라이드를 함께 확인. `useDeck.renderThumb`(렌더러 `renderThumbnailToContainer`)로 다음 슬라이드 썸네일 렌더.
- **출력 전체화면 버튼**: 출력 창에 Fullscreen API 토글 버튼(마우스 멈추면 자동 숨김). 브라우저 크롬을 제거해 프로젝터에 물리 화면 전체로 송출. 전체화면 진입 시 `resize` 로 slide scale 재계산되어 화면을 정확히 채움. (Fullscreen API 는 해당 창의 사용자 제스처로만 호출 가능 → 버튼은 출력 창 안에 위치.)

## 14.2 갱신 (2026-07-26) — 영상·음악 재생목록(수동 큐 + DnD)

- **재생목록 도입**: 기존 "목록에서 눌러 즉시 재생" 방식을 **소스에서 골라 담는 재생목록(수동 큐)**으로 개편. 영상은 세 소스(**PPT 내장 · R2 라이브러리 mp4 · 로컬 파일**)를 하나의 큐로 합치고, 음악은 R2 mp3 를 별도 큐로 담는다. `+` 로 담고 `×` 로 뺀다. 안정적 id(PPT 내장=`emb:<path>`, 라이브러리=`libv:<key>`, 음악=`mus:<key>`)로 중복 추가를 막고, 로컬 파일은 매번 고유 id 라 같은 파일도 여러 번 담김.
- **DnD 순서 변경**: `@dnd-kit`(core/sortable/utilities) 도입. 왼쪽 그립 핸들 드래그로 큐 순서 변경(`arrayMove`). 재생/삭제 버튼과 충돌 안 나게 4px 이동 후 드래그 시작. 재사용 컴포넌트 `SortablePlaylist.tsx`(도메인 로직 없는 프레젠테이션 컴포넌트, 영상·음악 공용).
- **수동 큐(자동 연속재생 아님, 사용자 확정)**: 항목별 재생 버튼 + 헤더 "다음"(현재 다음 항목, 없으면 첫 항목, 마지막이면 정지). 예배 진행자가 타이밍을 직접 제어. 재생 시 출력 창을 영상 모드로 전환하는 동작은 유지.
- **코드**: 신규 `src/present/playlist.ts`(아이템 타입/팩토리), `src/present/SortablePlaylist.tsx`(dnd-kit 정렬 목록). `ControlScreen.tsx` 사이드 패널을 "영상 재생목록 / 음악 재생목록"으로 재구성. 채널 메시지·출력 창(`OutputScreen`)은 기존 그대로(재생목록은 조작 창 로컬 상태, 재생 지시만 기존 메시지로 전송).

## 14.3 갱신 (2026-07-26) — 조작 창 UI/UX 개편 (레이아웃·톤 통일)

기능은 그대로 두고 조작 창 레이아웃/비주얼만 다듬음(사용자 요청: 레이아웃/공간 배치 + 비주얼 톤 통일).

- **슬라이드 미리보기 가로 배치**: 현재+다음 슬라이드를 세로로 쌓던 것을 **가로 2단**(`sm:grid-cols-[1fr_248px]`)으로. 좌측 현재 슬라이드(크게, `현재 슬라이드` 배지)+그 아래 이전/다음 네비, 우측 다음 슬라이드 컴팩트 카드. 좁은 화면은 자동으로 세로 접힘. 다음 썸네일은 컬럼 폭에 맞춰 `renderThumb(..., 216)`. 영상 모드 배지는 우측 상단으로 분리.
- **사이드바 탭 패널화**: 세로로 길게 쌓이던 영상/음악 두 카드를 **[영상][음악] 탭 하나**로 통합해 세로 사용량·중첩 스크롤 해소. 각 탭은 **재생목록(큐)=주 영역**(높이 채움, 내부 스크롤) + **"소스에서 추가"=하단 보조 영역**(`max-h-[46%]`)으로 분리. 사이드는 `lg:sticky lg:h-[calc(100vh-7rem)]`로 뷰포트에 고정.
- **비주얼 톤 통일**: 앱 디자인 토큰 기준으로 `shadow-sm` 카드, `bg-secondary` 세그먼트 컨트롤(출력 모드 토글과 동일), 영상=info(파랑)/음악=success(초록) 유지. "다음"=톤 배경 알약 버튼, 담기 `+`=공통 `AddButton` 컴포넌트로 통일, 재생/제거 hover 상태 정리, 빈 큐는 아이콘+안내 문구의 빈 상태로.
- **코드**: `ControlScreen.tsx` 만 변경(JSX/클래스 + `tab` 상태, 파일 하단 `AddButton` 헬퍼 추가). 채널·`OutputScreen`·재생목록 로직 불변.
